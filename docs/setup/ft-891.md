# Yaesu FT-891 Setup

## Supported Scope

Rolling Thunder uses the Yaesu FT-891 Enhanced CAT interface for:

- connection state
- current VFO-A frequency
- current receive mode
- background polling and recovery
- operator-confirmed receive-only frequency and mode changes
- best-effort regular-memory band context for cross-band receive tuning
- a timed manual band/ATAS-120 warning after a successful cross-band tune

Rolling Thunder does not use the Standard Com Port and does not provide PTT,
MOX, keying, tuner, power, or unattended transmit control.

## USB Device Selection

The installed FT-891 presents two Silicon Labs CP2105 serial interfaces.

Use only the Enhanced Com Port:

```text
/dev/serial/by-id/usb-Silicon_Labs_CP2105_Dual_USB_to_UART_Bridge_Controller_011F42E9-if00-port0
```

Do not configure the Standard Com Port:

```text
/dev/serial/by-id/usb-Silicon_Labs_CP2105_Dual_USB_to_UART_Bridge_Controller_011F42E9-if01-port0
```

Inspect the current device links with:

```bash
ls -l /dev/serial/by-id/
```

The `/dev/serial/by-id` path is required because `/dev/ttyUSB*` numbers may
change after reconnecting the radio.

## Serial Settings

Use:

- baud rate: 38,400
- data bits: 8
- parity: none
- stop bits: 2
- timeout: 1.0 seconds unless troubleshooting requires a temporary adjustment

The local user must have permission to open the serial device. Verify with:

```bash
id
ls -l /dev/serial/by-id/
```

On the validated Pi, user `geoff` is a member of `dialout`.

## Configuration

Example real-radio and mock-GPS configuration:

```yaml
hardware:
  mock: true
  radio_mode: real
  gps_mode: mock
  radio_device: /dev/serial/by-id/usb-Silicon_Labs_CP2105_Dual_USB_to_UART_Bridge_Controller_011F42E9-if00-port0
  radio_baud_rate: 38400
  radio_timeout_s: 1.0
  gps_device: null
```

Do not place the Standard Com Port in `radio_device`.

## CAT Commands Used

Read-only state:

```text
FA;
MD0;
```

Exact receive-only changes:

```text
FA#########;   set VFO-A frequency
MD0x;          set main receive mode
```

Best-effort cross-band context uses the operator-programmed regular memories:

```text
MCxxx;         select regular memory xxx
MC;            read selected regular memory
MA;            copy selected memory to VFO-A
```

Rolling Thunder never writes these memories. `MW` and `MT` are outside the
approved path.

The configured regular-memory map is:

| Memory | Band |
| --- | --- |
| `001` | 160 m |
| `002` | 80 m |
| `003` | 40 m |
| `004` | 30 m |
| `005` | 20 m |
| `006` | 17 m |
| `007` | 15 m |
| `008` | 12 m |
| `009` | 10 m |
| `010` | 6 m |

The older `BSxx` encoder is not the authoritative checkpoint-8 band-state
mechanism. The unresolved FT-891 CAT/front-panel band-context behavior is
tracked in issue #149.

## Required Command Order

Same-band receive tuning:

```text
1. Set exact target frequency with FA#########;.
2. Read FA; and verify the exact frequency.
3. Set mode with MD0x; when needed.
4. Read MD0; and verify the mode.
```

Cross-band receive tuning:

```text
1. Select the mapped regular memory with MCxxx;.
2. Read MC; and verify the selected memory.
3. Copy that memory to VFO-A with MA;.
4. Read FA; / MD0; and verify the recalled frequency belongs to the target band.
5. Set exact target frequency with FA#########;.
6. Read FA; and verify the exact frequency.
7. Set mode with MD0x; when needed.
8. Read MD0; and verify the mode.
9. Present the operator handoff:
   SET BAND TO <BAND> METERS — TUNE ATAS-120
```

A direct cross-band frequency change remains guarded before an unapproved raw
frequency jump can occur.

A failed memory-context check stops the ordered tune. A successful memory recall
is only best-effort band context; it is not treated as proof that the FT-891
changed its authoritative operator-visible band state.

## Two-Press Shared-Spot Operation

POTA and DX use the same two-press contract:

```text
first encoder press
    -> stage the exact selected spot
    -> no CAT
    -> no radio change

second encoder press on the same still-valid spot
    -> submit the exact staged action
    -> ReceiveTuningService performs receive-only tuning
```

There is no third confirmation or execution press.

Changing selection, provider/context, band filter, mode filter, action-critical
spot data, pressing Back, or losing valid radio state clears staging.

## ATAS-120 Safety

Changing receive frequency or recalling a band memory does not mean the FT-891
is in the correct operator-visible band context and never means the ATAS-120 is
tuned.

After a successful cross-band shared receive tune, Rolling Thunder displays:

```text
SET BAND TO <BAND> METERS — TUNE ATAS-120
```

Warning behavior:

- same-band frequency or mode changes show no band/ATAS warning
- a successful cross-band tune shows the target-band manual handoff
- the message appears in amber at higher priority than the normal tune result
- the message expires automatically after 10 seconds
- Back does not acknowledge or dismiss the timed warning
- Back retains its staging/selection cancellation behavior

The operator must manually set or confirm the target band and tune the ATAS-120
before transmitting.

The software must never claim the antenna is safe merely because exact receive
frequency and mode read-back succeeded.

## Troubleshooting

### Radio does not connect

Check:

```bash
ls -l /dev/serial/by-id/
id
```

Confirm:

- the USB cable is connected
- the configured path ends in `if00-port0`
- the path exists
- the user has serial-device permission
- the radio CAT baud rate is 38,400
- no other program has the Enhanced CAT port open

### Device path changed

Do not replace the stable by-id path with a temporary `/dev/ttyUSB*` number.

Reconnect the USB cable and inspect:

```bash
ls -l /dev/serial/by-id/
```

### Polling reports an error

The application should:

- preserve the last known frequency and mode
- report visible error state
- close the failed transport
- continue polling
- reconnect automatically when the device returns

### Memory-context verification fails

Stop the ordered tune. Do not continue to exact frequency or mode changes.

Confirm:

- memories `001` through `010` contain the intended band presets
- `MC;` reports the expected selected memory
- `MA;` recalls a VFO-A frequency within the requested target band
- the Enhanced CAT port is being used

Do not use `MW` or `MT` while troubleshooting Rolling Thunder.

### Frequency or mode verification fails

Stop the sequence and leave the error visible.

Do not retry through a parallel direct command path.

### Band/ATAS warning does not appear

Confirm the completed receive-tuning result reports `band_changed=True` and a
target band. A same-band tune intentionally produces no warning.

The expected cross-band message is:

```text
SET BAND TO <BAND> METERS — TUNE ATAS-120
```

## Live-Test Rules

Live FT-891 write testing must:

- occur while parked
- remain receive-only
- use the Enhanced CAT port only
- confirm the Standard TX-capable port remains closed
- verify first press stages with no radio change
- verify same-band second-press exact receive tuning
- verify cross-band second-press exact receive frequency/mode tuning
- treat regular-memory recall as best-effort band context only
- confirm same-band tuning shows no band/ATAS warning
- confirm cross-band tuning shows `SET BAND TO <BAND> METERS — TUNE ATAS-120`
- confirm the warning expires automatically
- verify staging invalidation on selection/filter/Back/radio loss
- leave `transmitting=False`
- avoid all PTT, MOX, keying, tuner, and power operations
- record results before pull-request approval

Checkpoint-8 physical acceptance of this contract is complete. Future work on a
more authoritative FT-891 band-state mechanism belongs to issue #149.
