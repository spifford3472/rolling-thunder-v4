# Yaesu FT-891 Setup

## Supported Scope

Rolling Thunder uses the Yaesu FT-891 Enhanced CAT interface for:

- connection state
- current VFO-A frequency
- current receive mode
- background polling and recovery
- operator-confirmed receive-only band selection
- operator-confirmed receive-only frequency and mode changes
- a sticky ATAS-120 retune warning after a verified band change

Rolling Thunder does not use the Standard Com Port and does not provide PTT,
MOX, keying, tuner, power, or unattended transmit control.

## USB Device Selection

The installed FT-891 presents two Silicon Labs CP2105 serial interfaces.

Use only the Enhanced Com Port:

```text
/dev/serial/by-id/usb-Silicon_Labs_CP2105_Dual_USB_to_UART_Bridge_Controller_011F42E9-if00-port0
```

Do not configure the Standard Com Port:

```text
/dev/serial/by-id/usb-Silicon_Labs_CP2105_Dual_USB_to_UART_Bridge_Controller_011F42E9-if01-port0
```

Inspect the current device links with:

```bash
ls -l /dev/serial/by-id/
```

The `/dev/serial/by-id` path is required because `/dev/ttyUSB*` numbers may
change after reconnecting the radio.

## Serial Settings

Use:

- baud rate: 38,400
- data bits: 8
- parity: none
- stop bits: 2
- timeout: 1.0 seconds unless troubleshooting requires a temporary adjustment

The local user must have permission to open the serial device. Verify with:

```bash
id
ls -l /dev/serial/by-id/
```

On the validated Pi, user `geoff` is a member of `dialout`.

## Configuration

Example real-radio and mock-GPS configuration:

```yaml
hardware:
  mock: true
  radio_mode: real
  gps_mode: mock
  radio_device: /dev/serial/by-id/usb-Silicon_Labs_CP2105_Dual_USB_to_UART_Bridge_Controller_011F42E9-if00-port0
  radio_baud_rate: 38400
  radio_timeout_s: 1.0
  gps_device: null
```

Do not place the Standard Com Port in `radio_device`.

## CAT Commands Used

Read-only state:

```text
FA;
MD0;
```

Receive-only changes:

```text
BSxx;          select band
FA#########;   set VFO-A frequency
MD0x;          set main receive mode
```

Supported band-selection values:

| Band | Command |
| --- | --- |
| 160 m | `BS00;` |
| 80 m | `BS01;` |
| 40 m | `BS03;` |
| 30 m | `BS04;` |
| 20 m | `BS05;` |
| 17 m | `BS06;` |
| 15 m | `BS07;` |
| 12 m | `BS08;` |
| 10 m | `BS09;` |
| 6 m | `BS10;` |

There is no dedicated FT-891 CAT band-selection value for 60 meters. Rolling
Thunder rejects that software band-selection request rather than guessing.

## Required Command Order

Cross-band receive tuning must occur in this order:

```text
1. Select band with BSxx;.
2. Read FA; and verify the selected band.
3. Set target frequency with FA#########;.
4. Read FA; and verify the exact frequency.
5. Set mode with MD0x; when needed.
6. Read MD0; and verify the mode.
```

A direct cross-band frequency change is rejected before an `FA` set command is
sent.

Same-band tuning skips step 1 but still verifies frequency and mode.

## ATAS-120 Safety

Changing the radio band or frequency does not mean the ATAS-120 is tuned.

After a verified band change, Rolling Thunder displays an amber warning in the
always-visible full-screen bottom ticker. The warning temporarily overrides
routine ticker status:

```text
BAND CHANGED TO <BAND> METERS — RETUNE ATAS-120
```

Warning behavior:

- same-band frequency or mode changes show no warning
- a cross-band result uses the verified target band
- the warning remains retained across POTA selection and filter changes
- a later same-band tune does not clear it
- a later band change replaces it with the new band
- Back or X explicitly acknowledges and clears it from any dashboard context
- Back clears the warning before cancelling an intent or clearing a row

The software must never claim the antenna is safe merely because CAT state
matches the requested receive frequency. Acknowledging the warning records only
that the operator saw it; it does not verify antenna tuning.

## Troubleshooting

### Radio does not connect

Check:

```bash
ls -l /dev/serial/by-id/
id
```

Confirm:

- the USB cable is connected
- the configured path ends in `if00-port0`
- the path exists
- the user has serial-device permission
- the radio CAT baud rate is 38,400
- no other program has the Enhanced CAT port open

### Device path changed

Do not replace the stable by-id path with a temporary `/dev/ttyUSB*` number.

Reconnect the USB cable and inspect:

```bash
ls -l /dev/serial/by-id/
```

### Polling reports an error

The application should:

- preserve the last known frequency and mode
- report visible error state
- close the failed transport
- continue polling
- reconnect automatically when the device returns

### Band verification fails

Stop the tuning sequence. Do not continue to frequency or mode changes.

Confirm:

- the requested band has a supported `BS` code
- the radio accepted the band-selection command
- `FA;` returned a frequency within the requested band
- the Enhanced CAT port is being used

### Frequency or mode verification fails

Stop the sequence and leave the error visible.

Do not retry through a parallel direct command path.

### ATAS warning does not appear

Confirm the completed receive-tuning result reported both:

- `band_changed=True`
- a verified `target_band`

A same-band tune intentionally produces no warning.

### ATAS warning remains visible

Use the existing Back action or X key to acknowledge it. The first Back action
acknowledges the warning before cancelling the tune intent or clearing the
selected POTA row.

## Live-Test Rules

Live FT-891 write testing must:

- occur while parked
- remain receive-only
- use the Enhanced CAT port only
- begin with a same-band change
- proceed to a controlled cross-band change
- verify every state through CAT read-back
- confirm same-band tuning shows no ATAS warning
- confirm cross-band tuning shows the verified target band warning
- confirm the warning remains until explicit acknowledgement
- confirm acknowledgement clears the warning
- leave `transmitting=False`
- avoid all PTT, MOX, keying, tuner, and power operations
- record results before pull-request approval
